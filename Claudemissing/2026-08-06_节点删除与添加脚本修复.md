# 节点删除彻底清理 + 列表创建时间 + 安装脚本地址参数化

日期：2026-08-06
阶段：方案设计（待确认）

## 问题现状

### 问题1：节点删除再重复添加有误
- DELETE 路由只删 Controller DB（7 张关联表 + Node 物理删除），Agent 端文件残留：
  - `/etc/myfw-agent/`（agent.yaml / ca.pem / agent.crt / agent.key）
  - `/var/lib/myfw-agent/`（node.id / salt / bootstrap_done）
  - `/usr/local/bin/myfw-agent` + `/etc/systemd/system/myfw-agent.service`
- 删除后 systemd 仍拉起 Agent，旧证书重连 -> `checkAuth` 找不到证书记录
- `autoReregister` 开启时，CA 验证通过会自动补录 node+cert，**节点"复活"**，与删除语义冲突
- 即使关闭 autoReregister，Agent 无限重连失败；本地 node.id 还在，重新添加行为不可预期

### 问题2：列表只显示最后活跃，无创建时间
- `Nodes.vue` 列表有 `last_seen` 列，无 `created_at` 列
- 后端 `GET /api/v1/nodes/list` 返回 `model.Node`（含 `CreatedAt`），无需改后端

### 问题3：安装脚本地址写死
- `handleGenerateScript` 中 `host = window.location.hostname`（动态），但端口 `8080`（下载）/`9090`（gRPC）写死
- 若用户改 docker-compose 端口映射（如 `18080:8080`），脚本里 8080 不可达
- Controller 迁移到其他服务器，旧脚本失效；新服务器地址/端口无法通过当前页面推断 gRPC 端口

## 方案

### 问题1：双保险彻底清理

#### A. Controller 主动下发注销指令（在线节点）
1. `proto/myfw/v1/stream.proto` 新增消息：
   ```proto
   message DecommissionCommand {}
   ```
   挂到 `ControllerToAgent.payload` oneof（第 10 个字段 `decommission`）
2. 重新生成 protobuf（`make proto` 或 `buf generate`）
3. `internal/controller/stream/stream.go` 新增 `SendDecommission(ctx, nodeID) error`（复用 `Reg.Send`）
4. `node_routes.go` DELETE 路由改为：
   - 先 `streamSvc.SendDecommission(id)`（在线才发，离线忽略错误）
   - 事务内：关联表物理删除 + **Certificate 标记 `revoked=true`**（保留指纹防复活）+ Node 物理删除
5. Agent `handler.go` 新增 `OnDecommission`：
   - `systemctl stop/disable myfw-agent`
   - 删除 `/etc/myfw-agent/`、`/var/lib/myfw-agent/`、`/usr/local/bin/myfw-agent`、unit 文件
   - `os.Exit(0)`
6. `conn.go` Handler 接口 + RX 分发新增 `OnDecommission`

#### B. Agent 自毁兜底（离线节点）
- `cmd/agent/main.go` 连接循环：`conn.Loop` 返回错误后，按 gRPC status code 判定：
  - `codes.Unauthenticated`（certificate revoked / unknown certificate）-> 自毁
  - `codes.PermissionDenied`（node archived）-> 自毁
  - 其他（网络/Unavailable）-> 退避重试（现有行为）
- 自毁逻辑同 A.5，抽成 `selfDestruct(log)` 函数复用

#### C. Certificate 保留 revoked 记录（防 autoReregister 复活）
- DELETE 时 `UPDATE certificates SET revoked=true WHERE node_id=?`（不物理删）
- `checkAuth` 查到 `row.Revoked` 返回 `certificate revoked`（现有逻辑）
- `autoReregister` 只在"无证书记录"时补录；记录存在且 revoked -> 走 revoked 分支，**不复活**
- 保留已吊销证书指纹：拒绝重连 + 审计追溯（安全设计，非冗余记录）

### 问题2：列表加创建时间列
- `Nodes.vue` 列表新增"创建时间"列，显示 `row.created_at`，设为常用列（始终显示）
- "最后活跃"列改为可收纳（保留）
- 列顺序：主机名/IP/后端/状态/系统/标签/**创建时间**/最后活跃/证书过期/操作

### 问题3：安装脚本地址参数化
- 添加节点对话框新增"Controller 访问配置"三项（可编辑）：
  - Controller 地址：默认 `window.location.hostname`
  - 下载端口：默认 `window.location.port || '8080'`（用户用非标准端口访问 Web 时自动适配）
  - gRPC 端口：默认 `'9090'`（浏览器无法推断，固定默认，用户可改）
- 脚本模板用这三个变量替换写死的 `${host}:8080` / `${host}:9090`

## 风险
- proto 重新生成需 `buf` 工具链；若环境无 buf，手改 pb.go 风险高 -> 优先用 buf
- Agent 自毁误触发：仅当明确收到 Unauthenticated/PermissionDenied 才自毁，网络错误不触发
- Certificate 保留 revoked：长期累积 revoked 记录，可纳入 retention 清理（后续）

### selfDestruct bug 修复（远程验证发现）
- 初版 selfDestruct 调 `systemctl stop myfw-agent`，但当前进程就是 myfw-agent，stop 杀掉自身导致后续删文件未执行（日志停在 `self-destructing`，无 `self-destruct complete`）
- 修复：去掉 systemctl stop，先 disable 再删文件，最后 os.Exit(0)（exit 0，systemd Restart=on-failure 不重启）
