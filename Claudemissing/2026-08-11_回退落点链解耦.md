# 回退落点链解耦（chain_id）

> 2026-08-11。第三批 P1a"组链解耦"经评估为过度设计，回退至"组即落点"（v1.2 语义）。

## 一、背景

第三批 P1a 引入 `ChainID`（落点链）与 `GroupID`（所属组）解耦：模板/实例可填 `chain_id` 指定独立落点链，0=继承组链。设计意图是允许"UI 分类 ≠ iptables 命令落点"。

实践问题：
- 99% 场景分类=落点，`chain_id` 字段是噪音
- 前端"所属组"+"落点链"双下拉选项相同，用户困惑"两者区别"
- 解耦想覆盖的场景（跨组落链、DNAT 归业务组展示）要么用更简单方式可解决（DNAT 直接归 nat 表组），要么当前规模用不上

## 二、决策

删除 `chain_id` 整层抽象，落点永远 = `group_id`（组即落点）。

## 三、删除范围

| 层 | 删除内容 |
|---|---|
| 模型 | `PolicyTemplate.ChainID`、`NodePolicyInstance.ChainID` 字段 |
| 编译 | `compileInstances` 的 `ChainID` 优先逻辑 -> 直接用 `GroupID` |
| API | `template_routes` 的 `chain_id` 入参/校验/diff/同步/字段标签/`checkTemplateChain` |
| 引用检查 | `custom_chain_routes` 的 `OR chain_id` 分支、`chainReferencedInstances` 的 `OR chain_id` |
| 前端 | `TemplateLibrary`/`NodePolicies` 的"落点链"下拉、`chain_id` 表单字段与 watch |
| 测试 | `TestCompileForNodeChainIDPreferred`、`TestCompileForNodeChainIDFallbackToGroup`、`TestCreateTemplateWithChainID`、`TestCreateTemplateRejectsMissingChain` 删除；`TestDeleteChainRejectedWhenReferenced` 改用 `GroupID` |

## 四、保留

- **多钩子 `Mounts`**：一条链挂多个父链 jump，与解耦无关，独立能力保留
- **P2 生命周期**：`chain_unavailable` 标记 + 禁用链审计（`chain.disabled` 含 `affected_instances`）；落点链 = `group_id` 链，检查逻辑简化
- **P3 表一致性**：`rulespec.Spec.ChainTable` + DNAT/SNAT 须 nat 表校验保留；`ChainTable` 来源从"chain_id 链或 group_id 链"简化为"group_id 链的 table"
- `policy.Fields.ChainTable`、`fieldsFromTemplate`/`fieldsFromInstance` 的 `chainTable` 参数保留（P3 仍需）

## 五、DB 列处理

`ChainID` 是 v1.3 新增列，存量数据都是 0。删 struct 字段后 GORM `AutoMigrate` 不会主动 drop 列，`chain_id` 列残留但代码不再读写（无害）。如需彻底清列另行单独 migrate，不阻塞本次回退。

## 六、TDD 节奏

- 红：删 `chain_id` 相关测试用例；P3/P2 用例去掉 `chain_id` 引用（改用 `group_id` 路径）
- 绿：删模型字段 + 编译/API/前端实现引用
- 验证：`go build ./...` + `go test ./...` + `go vet` + `vite build`

## 七、影响面

后端 6 文件 + 前端 2 文件 + 测试 3 文件 + 文档 2 文件。零 proto/Agent 变更（chain_id 从未跨 gRPC 边界）。
