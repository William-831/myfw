# 2026-08-17 待确认区状态丢失 + 禁用误标"下发待确认"修复

## 摘要

修复 `NodePolicies.vue toggleEnabled` 两个 bug:① dispatch 异步,操作后立即刷新保护期查不到 `confirm_wait` → 待确认区没状态、须刷新页面才见;② 禁用未下发实例(applied=false)无条件 dispatch → 后端产生无意义任务且 `change_type` 误标 `'dispatch'`(待确认区显示"节点策略下发待确认")。全程 TDD 红-绿,2 新用例 + 2 旧用例修正。

## 诊断

### 根因一(现象1/2:待确认区没状态、禁用后刷新才有):dispatch 异步,刷新时机过早
`toggleEnabled` 乐观翻转 + `dispatchNode` 后**立即** `refreshInflight()` + `guard.refresh()`,但 dispatch 异步——任务此刻在 `dispatching/applying`,未到 `confirm_wait`:
- ConfirmGuard 面板 `loadTasks({status:'confirm_wait'})` 返回空 → **待确认区没状态**(现象1)
- NodePolicies `nodeInGuard=false` → banner/"⏳ 待确认"标签不显示;5s 条件轮询首次 tick 要等 5s;刷新页面+点击节点会立即 `refreshInflight`,此时任务已 confirm_wait → 状态出现(现象2)

### 根因二(现象3:只显示"节点策略下发待确认"):禁用未下发实例误产生 dispatch 任务
`toggleEnabled` 无条件 `dispatchNode`。后端 Submit 的 disabling 查询要求 `applied=true`(coordinator.go:1051-1053),禁用未下发实例(applied=false)不匹配 → names 空 → `change_type` 落 default `'dispatch'`(coordinator.go:1134)、`policy_name` 保留默认"节点策略下发"(coordinator.go:156,仅 names 非空才覆盖)。且该场景节点本无规则可移除,不应产生保护期任务。

## 方案

1. **禁用且 applied=false**(节点无规则)→ 只 `updateInstance`,不 `dispatchNode`,提示"已禁用(未下发,无规则需移除)"
2. **dispatch 后拿 taskID**,fire-and-forget `pollTaskDone` 等 `confirm_wait`,再 `refreshInflight + guard.refresh + loadInstances`(不阻塞 UI,乐观翻转已即时反馈;与 `handleDispatch` 同模式)

## 产出

- `web/src/views/NodePolicies.vue`: `toggleEnabled` 两处修复(disabling 未下发短路 + confirm_wait 后台联动)
- `web/src/__tests__/NodePolicies.toggle.test.js`: 新增 2 用例(禁用未下发不 dispatch、confirm_wait 后联动刷新);2 旧用例补 `applied:true` 前提(禁用已下发实例才走 dispatch,与新语义一致);hoisted api 加 `getTask`

## 验证

- `npx vitest run`: 35 用例全绿(原 33 + 新 2)
- `npm run build`: 生产构建成功

## 决策记录

- **后端不改**: `change_type` 分类逻辑已正确(TestRefreshNodePreview 覆盖 disable/mixed),根因在前端无条件 dispatch;禁用已下发实例 → `'disable'` 已被后端正确处理
- **后端 Submit 不加"无变更检查"**(防过度设计): 前端 toggleEnabled(短路未下发)/handleDispatch(已检查 pending/disabling)均已堵,无其他入口产生空任务
- **pollTaskDone 后台收敛而非串行 await**: 保住乐观翻转的即时反馈语义(原注释明确为此去掉阻塞等待),改为 fire-and-forget 收尾刷新
