# 2026-08-19 前端刷新白屏 + 侧边栏偶发不跳转 修复部署

## 用户报告

- 最左侧侧边栏切换页面时，有时点了不跳转
- Ctrl+R 刷新页面会白屏

## 根因（浏览器启发式缓存）

`gin` 的 `c.File`（底层 `http.ServeFile`）**不发 `Cache-Control`**。浏览器对无缓存控制的响应按
`(Now - Last-Modified) × 10%` 判定新鲜度——`index.html` 长期不变后浏览器将其当"新鲜"缓存住，
刷新拿到的仍是**旧版 index.html**，其引用的旧哈希 chunk 在后端新构建后已不存在 → JS 加载失败 →
**白屏 / 路由守卫异常导致点击不跳转**。侧边栏点击偶发不跳转是同一根因的次生表现（旧版前端
与新版后端 API 不兼容，页面状态异常）。

## 修复（`internal/controller/server/server.go` newWebHandler，409-430 行）

显式缓存策略，杜绝启发式缓存：

- `/download/agent/linux-amd64`、`/download/ca.pem`：`Cache-Control: no-cache`（防节点缓存旧版 agent）
- `/assets/*filepath`：`Cache-Control: public, max-age=31536000, immutable`（Vite 哈希文件名内容不可变，强缓存一年零副作用）
- `NoRoute`（兜底 SPA 入口 index.html）：`Cache-Control: no-cache`（**核心**：每次刷新重新验证，拿到最新 index.html）

## 部署（192.168.80.249）

- 交叉编译：`CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -ldflags="-s -w -X main.version=fix-frontend-cache" -o dist/myfw-controller-linux-amd64 ./cmd/controller`
- scp → docker cp 替换容器内二进制（备份 .bak.*）→ docker restart
- 验证通过：
  - `--version` = `fix-frontend-cache`
  - `/healthz` = `{"status":"ok"}`
  - GET `/` → `Cache-Control: no-cache`
  - GET `/assets/index-BhBPYWbR.js` → `Cache-Control: public, max-age=31536000, immutable` + `text/javascript`

### HEAD vs GET 验证陷阱（重要，下次勿踩）

- gin 只注册 GET 路由，**HEAD 请求不匹配 assets 路由，落入 NoRoute 返回 index.html（no-cache）**
- `curl -sI`（HEAD）验证响应头会误判"assets 缓存策略未生效"——**必须用 GET**：`curl -sD - -o /dev/null <url>`
- 真实浏览器加载 JS/CSS 用 GET，行为正确，无实际影响
