# 策略创建/下发链路审查与修复（7 项）

日期：2026-08-07

## 摘要

审查前端创建 → 后端 CRUD → rulespec 校验 → 编译器 → dispatch → iptables driver 全链路，发现并修复 1 个实际 bug + 3 处复杂/边界不清 + 3 处技术债。

## 决策与改动清单

### #1 前端命令预览 source_group 缺 MYFW- 前缀（实际 bug）

- 现象：前端预览显示 `--match-set whitelist-ssh src`，实际下发 `--match-set MYFW-whitelist-ssh src`（Agent syncSets 建 `MYFW-<name>` ipset）。
- 修：`web/views/NodePolicies.vue` MARK 分支(:224) 与普通分支(:237) 补 `MYFW-` 前缀，与后端 `formatRuleLines` 一致。

### #2 Direction 字段语义收口（仅 MARK 白名单用）

三套方向机制并存，`Direction` 字段语义不清。收口为：**Direction 字段仅供 MARK 白名单**（FORWARD/INPUT 决定 ACL 链落点）。

- `rulespec.go`：非 MARK 动作 Direction 须为空（新增校验）。
- `template_routes.go`：POST 直接新建/模板实例化 + PUT 更新统一强制清空非 MARK 的 Direction；`fieldsFromInstance`/`fieldsFromTemplate` 非 MARK 时传空 Direction。
- `compiler.go`：`compileInstance` 兼容旧数据，非 MARK 强制清空 Direction。

### #3 抽 `rulespec.IsMarkWhitelist(action, source, sourceGroup, portRange)` 单一真相源

原"MARK 白名单拦截"判定在 compiler.go:109/362 与 template_routes.go:234/297 四处重复。抽为 `rulespec.IsMarkWhitelist`，四处复用。

### #4 删除 MarkACLGroupID 死字段

字段从未被编译器读取（MARK ACL 链硬编码 MARKACL-FWD/IN），却残留在模型/PolicyInput/引用检查/前端表单，且引用检查会误阻组删除。全部删除：
- `model/policy.go`、`model/policy_template.go`、`model/models.go`(迁移) 、`policy.go`(PolicyInput+3处写入)、`template_routes.go`(body+2处复制+sync)、`custom_chain_routes.go`(引用检查)、前端 NodePolicies.vue / TemplateLibrary.vue、docs/template-io-design.md。

### #5 dispatch 语义表述（全量对齐）

- 后端 `CompileForNode` 全量编译 enabled 实例（全量同步），前端原来暗示增量。修：按钮改"下发节点(全量对齐)"，`handleDispatch` 同时检查待下发 + 待移除实例，无变更才提示"无需下发"（原来漏查待移除实例）。

### #6 MatchMark 注释明确（仅供编译内部）

模型/PolicyInput 注释：MatchMark 仅供 MARK 白名单编译内部使用（匹配已打标流量），非用户输入，前端已移除入口。

### #7 修复旧测试（group_id 必填）

根因：`policy.validate()` 要求 `GroupID != 0`，旧测试建 Policy 不传组。
- `policy_test.go`：加 `mustCreateChain` helper，测试传 GroupID；`openTestDB` 补 `t.Cleanup` 关 sqlite 句柄（Windows TempDir 清理）。
- `compiler_test.go`：**重写为新模型测试**——原测试建 `Policy` 但 `CompileForNode` 编译的是 `NodePolicyInstance`（两套表，永远失败）。改为 `mustCreateInstance` 直接建实例；标签交集测试改用 `c.TargetNodes`（标签选择属 Policy 层）。
