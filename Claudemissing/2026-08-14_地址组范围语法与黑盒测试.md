## 一、现状

### 地址组全链路
- **模型** `internal/model/address_group.go`:`Members` 为 JSON CIDR 字符串数组(如 `["10.0.0.0/8","192.168.1.0/24"]`)。
- **校验** `address_group_routes.go:validateAddressGroupInput`:仅认单 IP 或 CIDR,裸 IP 视为 /32。
- **规范化** `address_group_routes.go:normalizeMembers`:裸 IP 补 /32(IPv4)/128(IPv6),去空白空项。ipset `hash:net` 要求 CIDR。
- **编译** `compiler.go:loadAddressSets`:Members 直喂 AddressSet 期望态,driver 下发 ipset。
- **仿真** `engine.go:ipInAnyCIDR`:遍历成员 `ipInCIDR` 匹配(ipset 无状态语义)。
- **前端** `AddressGroups.vue`:`el-select multiple allow-create`,逐条回车;命令预览复刻 ipset 编译。

### 仿真引擎地址组测试覆盖

## 二、需求 2:CIDR 范围语法

### 算法:range2cidr(经典)
将 `[start, end]` 展开为最少 CIDR 列表。用 `big.Int` 实现(IPv4/IPv6 通用):
```
for s <= e:
    lowbit = s & -s              // s 最低 set bit(对齐约束:块起始须 = s)
    if s == 0: lowbit = 2^bits
    rng = e - s + 1              // 不越界约束:块大小 ≤ rng
    blockSize = floorPow2(min(lowbit, rng))
    k = bits - log2(blockSize)
    输出 s/k
    s += blockSize
```
- `floorPow2(x) = 1 << (x.BitLen()-1)`
- `k = bits - (blockSize.BitLen()-1)`

**手算验证** `192.168.80.130-192.168.80.180`:
`130/31, 132/30, 136/29, 144/28, 160/28, 176/30, 180/32`(7 条,覆盖 130-180)✓

### 改动点(后端 `address_group_routes.go` 同包)
1. 新增 `rangeToCIDRs(start, end netip.Addr) []string`(新建 `cidr_range.go`,含 big.Int 辅助)。
2. `normalizeMembers` 增强:识别 `IP1-IP2`(含 `-` 且非 CIDR)→ `rangeToCIDRs` 展开 → 追加 CIDR;保留裸 IP 补 /32、CIDR 直通。
3. `validateAddressGroupInput` 增强:识别 `IP1-IP2`,校验两端合法、同族、`start <= end`。

### 改动点(前端 `AddressGroups.vue`)
- 输入提示:"输入 CIDR 或 IP 范围(如 10.0.0.0/8 或 192.168.80.130-192.168.80.180)后回车"。
- 命令预览:范围成员标注"保存时自动展开为 CIDR",不在前端重复算法;保存后 `loadData` 拉回展开结果展示。

### 不扩展 source/destination 单值字段
iptables `-s/-d` 单值,范围展开需拆多规则,语义变化。仅地址组 members(批量场景)支持。

## 五、决策点(已按推荐执行,如有异议可回退)
1. 范围语法:完整两端 `IP1-IP2`,不支持简写(歧义)。
2. 展开时机:写入时展开存储 CIDR。
3. source/destination 不支持范围。
4. 前端预览:标注自动展开,不在前端重复算法。
5. 黑盒测试:算法 + 写入 + 引擎边界,可选接口端到端。
