## 一、现状架构回顾(两级模型)

```
CustomChain(策略组=自定义子链,1:1 绑定)
├─ Name     —— 子链名,节点链 MYFW-<name>
├─ Parent   —— 钩子方向(单值):MYFW-INPUT/OUTPUT/FORWARD/PREROUTING/POSTROUTING/MANGLE
├─ Table    —— 表 filter/nat/mangle(与父链一致)
├─ Priority —— 父链中 jump 到本子链的顺序(全局调度)
└─ Enabled

PolicyTemplate(模板): 规则骨架 + GroupID 归属组(MARK 白名单 GroupID=0 落内置链)
NodePolicyInstance(实例): 从模板复制参数 + GroupID 归属组

编译链路: 实例 → compileInstance → CompiledRule.Chain = 组名
         → targetChainForRule 强制 Chain 非空(否则报"条目必须归属策略组")
         → driver 按 CustomChainDef 建链 + 父链单 jump + 规则落链
```

**核心耦合**: `组`(调度容器: 钩子/优先级)与 `子链`(规则落点) 1:1 绑死。
实例只有 `group_id` 一个落点字段, 编译强制 `Chain = 组名`, 无法独立选链。

## 二、架构级问题诊断

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| P1a | **落点不可独立于组** | 实例仅 `group_id`; `targetChainForRule` 报"chain is required(条目必须归属策略组)" | 想改规则落点必须换组(连带改钩子/优先级/表); 模板-实例归属与落点强绑定 |
| P1b | **单钩子** | `CustomChain.Parent` 单值; driver `syncCustomChains` 每链单 jump | 同一组规则无法同时作用于 FORWARD+INPUT; 需复制规则到多组, 维护翻倍 |
| P2 | **组生命周期隐式失效** | `compileInstances` 组不存在/未启用 → `continue` 静默跳过 | 禁用组 = 其下所有实例静默失效, 无标记/无审计/前端无感知; 排障靠猜 |
| P3 | **动作表一致性缺失** | rulespec 只校验 `nat_to` 非空; custom_chain_routes 只校验 Parent 白名单+Table 一致 | DNAT 规则放 filter 组链 → 编译期不拦截, Agent 执行 `-j DNAT` 才报错, 下发链路中途失败 |
| P4 | **MARK 白名单双链黑盒** | 3 条规则落平台内置链(MARKMANGLE/MARKACL-FWD/IN), compiler 动态追加 CustomChainDef | 用户不可见/不可管理这 3 条链(可选后置) |

## 三、目标架构

### 核心洞察(零 proto 改动的关键)

driver `syncCustomChains`(iptables.go:249)对每个 CustomChainDef:
`-N` 幂等(存在跳过) → `-C parent -j name` 检查 → 无则 `-A parent -j name` → `-F` 清链。
**同名链重复出现在 custom_chains(不同 parent)会被正确创建多条 jump**。
因此: **多钩子 = Compiler 把链的每个挂载展开为一条同名 CustomChainDef**, driver/Agent 零改动。

### 3.1 P1a 落点独立: 模板/实例加 `ChainID`

```
PolicyTemplate.ChainID     —— 落点链(CustomChain.ID), 0 = 继承 GroupID 组链(向后兼容)
NodePolicyInstance.ChainID —— 同上, 实例可独立于模板/组选落点

编译: 落点链 = ChainID > 0 ? ChainID 链 : 组链(GroupID)
MARK 白名单仍落内置链(ChainID 强制忽略, 规则由编译器生成)
```

意义:
- 实例/模板"归属组"(调度语义)与"落点链"(执行语义)解耦
- 存量数据 ChainID=0 行为完全不变

### 3.2 P1b 多钩子: CustomChain 多挂载

```
CustomChain 新增 Mounts(JSON []ChainMount, 权威字段)
  type ChainMount struct {
      Parent   string `json:"parent"`   // MYFW-INPUT/FORWARD/...
      Priority int    `json:"priority"` // 该父链中 jump 顺序, 值小排前
  }
Parent/Priority 保留为兼容字段(mounts[0] 的镜像, 供旧代码/旧数据回退)

读取(compiler/列表): Mounts 非空 → 用 Mounts; 空 → 回退 [{Parent, Priority}](存量零迁移)
写入(create/update): 前端提交完整 mounts 列表; 后端写 Mounts 并同步 Parent/Priority = mounts[0]

编译: loadCustomChains 按"链 × 挂载"展开为多条同名 CustomChainDef(不同 parent)
```

### 3.3 P2 组生命周期显式化

```
实例列表接口(GET /nodes/:id/instances): 每个实例补 chain_unavailable bool
  —— 落点链(ChainID/组链)不存在或未启用时为 true

前端: 实例卡片加 "⚠ 链不可用" 危险标签(替代静默)
审计: 禁用/删除组(链)时写 chain.disabled / chain.deleted, detail 含受影响实例数
编译: 跳过逻辑保留(链不可用时实例不参与编译), 但不再无感知
删除链: 引用检查保留(有策略/模板/实例引用拒绝删除)
```

### 3.4 P3 动作表一致性编译期校验

```
rulespec 增加 action 表要求(单一真相源):
  DNAT/SNAT → 落点链 Table 必须 nat
  ACCEPT/DROP/REJECT → 任意表(filter/nat/mangle 均合法)
  MARK → 白名单拦截落内置链(mangle+filter), 不校验用户链

三层校验:
  1. API 层(template_routes): 模板/实例保存时, 校验落点链 Table vs 动作
  2. 编译期(compiler.compileInstance): 落点链 Table vs 动作, 防旧脏数据绕过入口
  3. 前端: 命令预览表不匹配提示(红字警告)
```
