# 预置链删除不重建

## 摘要

预置常用自定义链(策略组)已存在(`internal/model/seed.go`),启动时由 `db.Migrate` 调用
`SeedCustomChains` 幂等播种 5 条。但当前逻辑"按 name 查不到就创建"每次启动都跑,
导致用户删除预置链后重启会被重建,违背"能成功删除"。

本次修复:引入一次性种子标记 `seed.custom_chains.v1=done`,首次播种成功后写入,
之后启动检查标记已存在则跳过播种。删除/编辑均不再被重启覆盖。

## 现状(回退后 50a60bf)

- `internal/model/seed.go`:`builtinCustomChains` 5 条(business-input/acl-forward/
  mark-mangle/nat-prerouting/nat-postrouting),`SeedCustomChains` 按 name 幂等创建。
- `internal/db/db.go:164`:`Migrate` 每次启动调用 `SeedCustomChains`。
- `internal/controller/server/custom_chain_routes.go`:CRUD 完整,删除有引用检查
  (策略/模板/实例引用本链则 409 拒绝)。
- `web/src/views/CustomChains.vue`:列表/新增/编辑/删除 UI 齐备。

## 问题

`SeedCustomChains` 每次 Migrate 执行,按 name 查不到即 Create:
- 用户删除 `business-input` → 重启 → name 查不到 → 重新创建 → "删除失败"。
- 用户编辑 `nat-prerouting` 的 priority → 重启 → name 存在跳过 → 编辑保留(此项无问题)。

## 方案:一次性种子标记(版本化 key)

利用已有 `SystemSetting`(key-value)表:

1. `SeedCustomChains` 开头查 `SystemSetting` key=`seed.custom_chains.v1`:
   - 若存在(value=`done`)→ 直接 `return nil`,跳过播种。
   - 不存在 → 进入播种流程。
2. 播种流程不变(按 name 查,不存在则 Create)。
3. 播种全部成功后,写入 `SystemSetting{Key:"seed.custom_chains.v1", Value:"done"}`。
   - 部分失败(某条 Create 报错)则不写标记,函数返回 error,下次启动重试(已建的跳过)。

### 版本化 key 的好处

未来预置链清单变更(如 v2 新增链),改 key 为 `seed.custom_chains.v2`,新键不存在 →
重新播种增量(已存在 name 跳过),老键保留不影响。无需单独迁移脚本。

### 语义

- 首次部署:空库 → 播种 5 条 + 写标记 → 用户直接可用。
- 用户删除某条:重启 → 标记已 done → 跳过 → 不重建。✅ "能成功删除"
- 用户编辑某条:重启 → 标记已 done → 跳过 → 编辑保留。✅ "能编辑"
- 用户新增自己的链:不受影响,正常 CRUD。✅ "能创建"

### 不做的事(防过度设计)

- 不加"恢复预置链"按钮:用户删了想恢复,可手动新建同名链(预置清单见文档/seed.go)。
  若后续有需求再加 system_routes 提供 `POST /api/v1/system/seed-chains/reset`。
- 不改 CustomChain model(不加软删除字段),不改前端,不改路由。
- 不清 DB 中 chain_id 列残留(回退遗留,代码不读写,无害)。
