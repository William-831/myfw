# 漂移治理修复方案（配置侧语义漂移 + 运行时 drift 来源分类）

> 日期: 2026-08-06
> 范围: 两个关联 bug——模板-实例同源关系治理弱、审计仪表盘 drift_count 无严重度分类
> 原则: 先方案确认,后 TDD 实施;分两批,第一批纯后端+前端不涉 Agent,第二批涉 proto+Agent 升级

---

## 一、诊断

### Bug 1: 模板-实例同源关系治理弱(配置侧语义漂移)

**现状链路**:
- 实例化(`POST /nodes/:id/instances`, template_routes.go:252-274): 全量复制模板参数 + 设 `SyncedSpecVersion` ✅ 同源建立
- 实例编辑(`PUT /instances/:id`, template_routes.go:321-366): 改实例参数, **不更新 SyncedSpecVersion、不断 TemplateID、无"已偏离"标记**
- `instanceDrift`(template_routes.go:505-510): 仅检测 `tpl.SpecVersion > inst.SyncedSpecVersion`(模板侧漂移)
- 节点列表角标(node_routes.go:45-55): 用 instanceDrift, 只计数量
- 实例列表(NodePolicies.vue:56): 仅 `⚠ 模板已更新` 标签
- sync(NodePolicies.vue:433 + template_routes.go:419): 全量覆盖, 无 diff 预览

**问题拆解**:
| 子问题 | 现状 | 影响 |
|---|---|---|
| 1a 实例偏离无标记 | 手动改实例参数后, SyncedSpecVersion 不动, TemplateID 保留 | 实例已偏离模板但系统无感知, "同源关系名存实亡" |
| 1b drift 无字段详情 | 角标/标签只显"有漂移" | 用户不知漂移了什么字段, 要逐个肉眼对比 |
| 1c sync 无 diff 预览 | handleSync 直接全量覆盖 | 怕丢手动定制, 认知负担大, 易误操作 |
| 1d 配置漂移未纳入可观测 | audit.go 只统计 `node.drift`(运行时) | 仪表盘 drift_count 不反映"模板-实例不同步", 与运行时 drift 割裂 |

**"复制后断裂"含义**: 实例化(复制参数)后实例与模板各自演化, 系统只在模板 SpecVersion 变时被动检测, 不维护"参数同源"的持续关系——实例手动偏离无标记、无反向检测。

### Bug 2: 运行时 drift 无来源分类(审计仪表盘 drift_count 无法反映严重度)

**现状链路**:
- Agent watchdog(watchdog.go:123-176): 周期 Hash 对比, 不一致即 ReportDrift
- `DriftReport`(stream.proto:48-54): 仅 node_id/expected_hash/actual_hash/detail/ts_unix, **无 source 字段**
- `Detail` 硬编码(watchdog.go:165): `"external modification detected in MYFW namespace"`——所有 drift 同一描述
- Controller 收到(stream.go:183-186): `auditDrift` 写 audit log `action=node.drift`, 无分类
- 仪表盘(audit.go:114,124): `drift_count = count(node.drift)`, 只计数; DailyStat.Drift(audit.go:77) 同样只计数
- 自愈: OnSync(stream.go:191) -> Coordinator.Submit(AutoConfirm=true, Scene=self_heal)

**问题**: 节点重启规则丢失(docker/k8s 重启、iptables 非持久化)与外部人工篡改(iptables -I/D)都报同一 `node.drift`、同一 detail, **仪表盘 drift_count 混为一类, 无法区分良性/恶性**。

## 二、修复方案

### 第一批: Bug 1 配置侧语义漂移治理(纯后端+前端, 不涉 Agent)

**目标**: 让"模板-实例不同步"可观测、可字段级 diff、可预览安全同步, 并纳入审计/仪表盘。

#### 1.1 实例偏离检测 + 字段级 diff
- 新增 `instanceDiff(inst, tpl) []string`: 返回实例与模板当前参数不一致的字段名列表(规则字段集, 同 templateSpecChanged 的字段集)
- `instanceDrift` 保留(模板 SpecVersion 判据), 新增 `instanceDeviated(inst, tpl) bool`(参数级偏离判据, 不依赖 SpecVersion)
- 实例列表接口(`GET /nodes/:id/instances`)返回扩展:
  - `drift`(模板侧, 已有) + `drift_fields []string`(模板侧变更字段, 模板当前 vs 实例快照)
  - `deviated`(实例侧手动偏离) + `deviated_fields []string`(实例当前 vs 模板当前)

#### 1.2 sync 预览接口
- 新增 `POST /instances/:id/sync-preview`: 返回 `{fields: [{field, current, template}], summary}`——不落库, 仅对比
- 前端 sync 前弹预览框展示字段级 diff, 用户确认后再调 `POST /instances/:id/sync`

#### 1.3 批量同步
- 新增 `POST /nodes/:id/sync-all`: 同步该节点所有 drift 实例, 返回 `{synced: n, skipped: m}`
- 前端节点列表 drift 角标加"一键同步全部"入口

#### 1.4 配置漂移纳入审计/仪表盘
- sync 操作已有审计(`auditInst sync`), 补: 实例偏离检测写入审计 `instance.deviated`(节点实例列表加载时若发现偏离, 异步写一条审计? ——**否, 太吵**)
- 改为: 仪表盘新增 `config_drift_count`(当前存在模板侧 drift 的实例数, 实时聚合, 非审计计数)
- `dashboard_routes.go` 新增 `/api/v1/dashboard/config-drift`: 返回各节点 drift 实例数 + 总数

#### 1.5 前端
- NodePolicies.vue: drift 标签改 `⚠ 模板已更新(N字段)`, tooltip 列字段; 新增"实例已偏离"标签(橙色); sync 改预览流程
- Nodes.vue: drift 角标保留, 加"一键同步"按钮
- 审计仪表盘: 加"配置漂移"卡片(config_drift_count)

**TDD**: instanceDiff/instanceDeviated 单测 → sync-preview 接口测试 → sync-all 测试 → 前端联调

### 第二批: Bug 2 运行时 drift 来源分类(涉 proto+Agent, 需 Agent 升级)

**目标**: 区分"重启规则丢失(良性)"vs"外部篡改(恶性)"vs"jump 顺序错位(自愈可恢复)", 仪表盘分类统计。

#### 2.1 DriftReport 加 source 字段(proto 变更)
```proto
message DriftReport {
  string node_id = 1;
  string expected_hash = 2;
  string actual_hash = 3;
  string detail = 4;
  int64 ts_unix = 5;
  DriftSource source = 6;      // 新增: 分类来源
  string diff_summary = 7;     // 新增: 规则 diff 摘要(缺失N/多出M)
}
enum DriftSource {
  DRIFT_SOURCE_UNSPECIFIED = 0;
  DRIFT_SOURCE_RESTART_LOSS = 1;    // 重启丢失: expected 规则缺失, 无陌生规则
  DRIFT_SOURCE_EXTERNAL_TAMPER = 2; // 外部篡改: 多出陌生规则或被改写
  DRIFT_SOURCE_JUMP_DISORDER = 3;   // jump 顺序错位: EnsureJumps 可恢复
}
```

#### 2.2 Agent watchdog 分类逻辑
- 检测 drift 时, 不仅比 hash, 还做规则 diff:
  - expected 规则集(上次 Apply 的 RuleSet, Agent 本地缓存) vs actual(iptables-save MYFW-*)
  - expected 全缺失 + 无陌生 -> RESTART_LOSS
  - 多出陌生规则 -> EXTERNAL_TAMPER
  - 仅 jump 顺序差异(EnsureJumps 修复后 hash 一致) -> JUMP_DISORDER, 不上报/自愈即恢复
- 需 Agent 缓存 expected RuleSet(当前只缓存 hash), 改动较大

#### 2.3 Controller 侧兜底分类(不依赖 Agent 升级的折中)
- 收到 DriftReport 后, 若 source 未填(旧 Agent), Controller 主动 `SendSyncRules` 拿 actual 规则, 与编译产物(expected) diff 分类
- 结合节点最近重连时间(heartbeat 间隙)辅助判定 RESTART_LOSS
- 优势: 旧 Agent 也能分类; 劣势: Controller 需缓存编译产物

#### 2.4 审计 + 仪表盘分类
- `auditDrift` 写 audit log 时 detail 带 source + diff_summary
- 仪表盘 `drift_count` 拆分: `drift_restart_loss / drift_external_tamper / drift_jump_disorder`
- DailyStat.Drift 拆分同上
- 前端审计页/仪表盘展示分类, 外部篡改红色高亮

**TDD**: watchdog 分类单测 → proto 生成 → Controller 兜底分类单测 → 仪表盘统计测试 → 部署验证
