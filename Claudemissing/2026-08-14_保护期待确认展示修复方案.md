# 保护期待确认展示修复(2026-08-14)

## 摘要

修复用户报告的节点策略页两个展示 bug:
1. 实例条目标签文案与操作意图脱钩(启动应显示"下发待确认",有时禁用后显示错误标签)
2. 保护期待确认区(顶部 banner + ConfirmGuard 抽屉)只显示泛化"节点策略",无具体策略名、无命令预览

## 根因

### Bug 1:实例条目标签基于可变 enabled 值
`NodePolicies.vue` 原实现 `pendingConfirmIds: Set<id>`,标签文案 `inst.enabled ? '⏳ 新状态待确认' : '⏳ 移除待确认'`
- 依赖 `inst.enabled` 当前值判断意图;`toggleEnabled` 乐观翻转后 `loadInstances()` 刷新实例,若 enabled 与本次操作错位(并发/竞态/后端返回旧值),标签错乱
- 文案"新状态待确认"与保护期面板语义("下发待确认")不一致

### Bug 2:移除任务(SubmitRemoval)预览缺失
`coordinator.go` SubmitRemoval 创建任务时:
- `PolicyName` 写死"节点策略移除"(无实例名)、`ChangeType` 为空、`DiffAfter` 为空
- approveAndDispatch 调 `refreshNodePreview` 走通用分支查 disabling(**排除 pending_delete=true 实例**),查不到本实例后 `fillNodeDispatchPreviewFromCache` 的 default 分支把 `ChangeType` **误覆盖为 "dispatch"**(移除任务应显示禁用语义)
- 结果:ConfirmGuard 显示"节点策略移除 + 下发待确认标签 + 无命令";顶部 banner fallback"节点策略"

## 修复方案

### 后端(coordinator.go)
1. `SubmitRemoval` 创建任务时填 `PolicyName=inst.Name`、`ChangeType="disable"`
2. `refreshNodePreview` 识别移除任务(`pending_delete_task_id = t.ID` 存在实例),走新增的 `fillRemovalPreview` 填充 `diff_after`(-D 移除命令,编译实例生成);不落入通用分支(避免 change_type 误覆盖)

### 前端
1. `NodePolicies.vue`: `pendingConfirmIds: Set<id>` → `pendingConfirmIntents: Map<id, 'dispatch'|'remove'>`
   - toggleEnabled → intent = v ? 'dispatch' : 'remove'
   - handleDeleteInst → intent = 'remove'
   - handleDispatch → 全部 enabled 实例 intent = 'dispatch'
   - 标签:dispatch → "⏳ 下发待确认", remove → "⏳ 移除待确认";状态标签联动"待确认"
2. 顶部 guardTask banner 显示 `policy_name` + `diff_after` 命令预览(小字 pre 展开,点击跳转确认)
3. `ConfirmGuard.vue` 卡片顶部显示 `policy_name`(📄 前缀)+ 变更类型标签,节点 IP 移至第二行
