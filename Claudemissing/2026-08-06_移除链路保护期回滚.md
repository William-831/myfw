# 2026-08-06 移除链路保护期回滚 + 下发状态同步

## 摘要

修复两个 bug：
1. **移除实例不删节点规则**：DELETE 直接物理删 DB，不触发 dispatch，节点规则成孤儿。
2. **下发后状态显示未下发**：前端 dispatch 后立即刷新，但后端异步，applied 延迟更新。

## 决策

### 移除链路（进保护期可回滚，非自动清理）

用户要求"移除进保护期，误删可回滚"。方案：

- `NodePolicyInstance` 加 `PendingDelete bool` + `PendingDeleteTaskID string`（精确关联 task，避免同节点多 task 误伤）。
- `DELETE /instances/:id`：
  - `applied=false`（节点无规则）-> 直接删 DB，204。
  - `applied=true`（节点有规则）-> 连接预检 -> 置 `enabled=false, pending_delete=true` -> `co.Submit(AutoApprove)` 拿 task_id -> 关联 `pending_delete_task_id` -> 返回 202 + task_id。
  - Submit 失败 -> 回滚标记，返回错误。
- `coordinator.Confirm`：事务内清理 `pending_delete=true && pending_delete_task_id=task_id` 的实例（用户确认移除）。
- `coordinator.Rollback` / `autoRollback`：恢复 `pending_delete=true && pending_delete_task_id=task_id` 的实例（`enabled=true, applied=true, pending_delete=false, task_id=''`），Agent 恢复快照后规则回来。

### 下发状态同步（前端轮询 task 终态）

- 封装 `pollTaskDone(taskID)`：每 1s 轮询 `getTask`，终态（confirm_wait/confirmed/failed/rolled_back）或 15s 超时停止。
- `handleDispatch`、`toggleEnabled`、`handleDeleteInst`（202 分支）复用，终态后再 `loadInstances()`。
