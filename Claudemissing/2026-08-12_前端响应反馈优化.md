# 2026-08-12 前端响应反馈优化(修 bug + 补轮询)

## 摘要

解决"部分操作执行完必须刷新页面才更改状态"的痛点。定位到**直接元凶为前端缓存失效前缀 bug**(写后失效是空操作),并补齐 Dashboard/Audit/Nodes/Approve 四个状态实时页面的轮询,后端 config-drift 加 5s 缓存。全程 TDD 红-绿。

## 诊断(三类根因)

### 根因一(直接元凶,致命 bug):缓存失效前缀与缓存键不匹配
`web/src/api/index.js:16-19`:
- `invalidateAfterWrite('nodes')` 用前缀 `'nodes'`,但缓存键是完整 URL `'/v1/nodes/list'`——`startsWith('nodes')===false`,**不删**
- `invalidateAfterWrite()`(dicts)用前缀 `'dicts'`,但字典键是 `'/v1/address-groups'`/`'/v1/marks'`/`'/v1/custom-chains'`/`'/v1/templates'`——**全不删**

后果:写后各页 `loadXxx()` 命中 TTL 旧缓存(节点 5s / 字典 30s),UI 不变;SPA 切路由不清 JS 内存,只有 **F5** 才重置。实例类操作(`getNodeInstances` 实时拉取)不受影响,故 NodePolicies 表现正常。受影响:AddressGroups/CustomChains/TemplateLibrary/Marks/Nodes 五页增删改。

### 根因二:状态实时页面无轮询
| 页面 | 问题 |
|------|------|
| Dashboard | `onMounted` 一次,KPI/漂移/审计时间线永不刷新 |
| Audit + AuditFeed | 无轮询无推送,审计不实时;AuditFeed 纯 props 静态展示 |
| Nodes | 在线状态/最后活跃不轮询,Agent 上下线后不更新 |
| Approve | 写后重载正常,但任务状态流转不轮询 |

### 根因三(架构层,留作演进):无 SSE 实时推送
项目无 SSE/WebSocket。后端已有可复用 pub/sub(`SubscribeTaskResults`/`broadcastTaskResult` stream.go:80/102)+ 事件源(Registry.Register/Deregister、coordinator result loop、`audit.Sink.Write` 统一入口)。当前 2-10 节点规模属过度设计,未引入。

## 方案(档一,用户确认)

1. 修 `invalidateAfterWrite` 前缀 bug + `cache.js` 加 `clear()` 全清
2. 复用 `usePolling` 补 4 处轮询:Dashboard 10s / Audit 10s / Nodes 15s / Approve 5s
3. `config-drift` 后端加 5s TTL 缓存(与 dashboard/stats 同策略,不额外加失效点)

## 决策记录

- **不引入 SSE/WebSocket**:当前节点规模(2-10)轮询足够,防过度设计;后端 pub/sub 基建已就绪,规模增长后演进路径清晰(Registry 连接事件 + coordinator 任务状态 + audit 事件 → SSE endpoint → 前端 useEventSource)
- **轮询间隔**:Dashboard/Audit 10s、Nodes 15s、Approve 5s(任务流转最快需感知);轮询刷新静默(silent 参数不置 loading),避免闪烁
- **config-drift 不额外加失效点**:与 dashboard/stats 一致靠 5s TTL(全项目现状),最坏 5s 延迟可接受
- **测试基建**:fakeTimers 下不能用 `flushPromises`(其 setTimeout 被 fake 挂起),用多轮原生 `Promise.resolve()` 冲刷 onMounted async 链;stub element-plus 表格需自定义 el-table-column 抑制 scoped slot(row 上下文缺失会崩)
