# 第二批设计 · 运行时 drift 来源分类

> 日期: 2026-08-11
> 关联: `2026-08-06_漂移治理修复方案.md`(第二批)
> 问题: 审计仪表盘 drift_count 无法反映严重度,节点重启规则丢失(良性)与外部篡改(恶性)混为一类。
> 决策: **采用 Controller 兜底分类(不升级 Agent/不改 proto)**,替代原方案 2.2 的 Agent 原生分类。

---

## 一、为什么弃用 Agent 原生分类(原方案 2.2)

原方案 2.2 需改 `DriftReport` proto + Agent 升级(全量),且**不解决根本问题**:
- Agent 只有 expected hash 无 expected 规则集(Apply 后未缓存 RuleSet),仍拿不到规则级 diff
- "缺失=重启还是篡改删除"的模糊性在 Agent 侧同样存在

**Controller 兜底的优势**:
- `comp.CompileForNode`(compiler.go:34)随时可拿 expected 编译产物(Controller 独有信息)
- `streamSvc.RequestRulesAndWait`(stream.go:387)可拉 actual 规则(Agent 已支持,`main.go:196` 注入 RulesCollector)
- 零 proto/Agent 变更,立即落地,旧 Agent 同样生效

## 二、分类模型

### source 枚举

| source | 含义 | 严重度 |
|---|---|---|
| `external_tamper` | 存在 expected 无的陌生规则(多出) | 🔴 恶性 |
| `rule_removed` | 无陌生规则,个别 expected 规则缺失 | 🟠 疑似篡改删除 |
| `restart_loss` | 无陌生规则,expected 大面积缺失 | 🟡 疑似重启丢失(良性,自愈即可) |
| `unspecified` | 无法分类(编译/拉取失败等) | ⚪ 未知 |

### 判定规则(启发式,诚实标注)

输入: `expected []*myfwv1.CompiledRule` + `actual []model.IptablesRule`(is_myfw=true)

1. 前置失败(编译失败/拉取失败/expected 为空)→ `unspecified`
2. `extra > 0`(actual 存在 expected 特征集外的规则)→ **external_tamper**(多出=最明确的篡改信号)
3. `extra == 0` 且 `missing >= 0.8 * expectedN` 或 `actualN == 0` → **restart_loss**(重启/清空)
4. `extra == 0` 且 `0 < missing < 0.8 * expectedN` → **rule_removed**(特定规则被删)
5. `extra == 0` 且 `missing == 0`(仅顺序/元数据差异,EnsureJumps 自愈场景)→ **unspecified**

### 规则 key 规范化(桥接 expected 结构化 vs actual iptables 行)

- expected key: `Chain|Action|Protocol|PortRange|Source`(CompiledRule 结构化字段)
- actual key: 从 `-A CHAIN -p tcp --dport 22 -s 1.2.3.4 -j ACCEPT` 解析同构字段
- 集合求差: actual 有 expected 无 = extra;expected 有 actual 无 = missing

> 说明: 启发式对比不求逐字精确(组引用/白名单骨架等复杂规则可能 key 不匹配),阈值与字段集可在实现时调优;分类标签只用于严重度提示,不改变自愈行为。

## 三、实现

### 新文件 `internal/controller/stream/drift_classify.go`

```go
// DriftClass 运行时漂移分类结果(启发式,仅严重度提示,不改变自愈行为)
type DriftClass struct {
    Source      string `json:"source"`       // external_tamper/rule_removed/restart_loss/unspecified
    ExpectedN   int    `json:"expected_n"`
    ActualN     int    `json:"actual_n"`
    Missing     int    `json:"missing"`
    Extra       int    `json:"extra"`
    Summary     string `json:"summary"`      // 中文摘要,审计/前端展示
}

// classifyDrift 纯函数(可单测):对比 expected 编译产物 vs actual 上报规则,输出分类
func classifyDrift(expected []*myfwv1.CompiledRule, actual []model.IptablesRule) DriftClass
```

辅助:
- `compiledRuleKey(cr *myfwv1.CompiledRule) string` — 结构化→key
- `parseActualRuleKey(line string) (string, bool)` — `-A CHAIN ...`→key(解析失败返回 false,跳过)

### 修改 `internal/controller/stream/stream.go` — auditDrift 异步分类

```go
// auditDrift 收到 drift 后:①同步写基础审计(现状);②异步 goroutine 分类,
// 编译 expected + 拉 actual + classify + 补写 node.drift.classified 审计。
// 异步不阻塞 stream 收包;分类失败(编译/拉取)回落 unspecified。
```

- `classifyAndAudit(ctx, nodeID, drift)`: goroutine 内调 CompileForNode + RequestRulesAndWait(3s 超时) + classifyDrift + `auditSink.Write(action="node.drift.classified", scene=AuditSceneSelfHeal)`
- stream.Service 需注入 compiler(当前 server.go 组装时注入 OnSync,类似方式注入 Compiler)

### 修改 `internal/controller/audit/audit.go` — 仪表盘分类统计

- `Dashboard()`: summary 增加 `drift_external_tamper / drift_rule_removed / drift_restart_loss / drift_unspecified`(按 `node.drift.classified` 的 detail.source 聚合)
- DailyStat 暂不加分类(避免过度),summary 先落地

### 修改前端 `web/src/views/Audit.vue`

- drift 卡片(drift_count)下方拆 3 类: 篡改(红)/删除(橙)/重启丢失(黄),点击可看明细

## 六、风险与边界

- **分类是启发式**: "缺失"无法 100% 区分重启丢失与篡改删除,阈值调优迭代;标签仅提示严重度
- **分类延迟**: 异步 3s 拉取,drift 审计分类非实时(基础审计实时)
- **开销**: 仅 drift 时分类,低频,可接受
- **诚实性**: 无法判定时回落 unspecified,不硬猜

### 部署验证(249)
- healthz/web/新 assets 全 200;审计 dashboard 返回 `drift_external_tamper` 等分类字段
- 249 触发真实 drift(加陌生规则 `-s 10.255.255.255 -j ACCEPT` 到 MYFW-INPUT):分类审计写入 `node.drift.classified`(expected_n=0 -> unspecified,因 249 无 enabled 实例,**正确回落**);自愈链路验证(OnSync 触发重新下发,陌生规则被自动清除)
- **发现并修复对齐 bug**:iptables `-S` 对单 IP 输出 `1.2.3.4/32`,而 `CompiledRule.Source` 存 `1.2.3.4`,key 不匹配会误判 missing+extra。修复:`normIP` 去 `/32` 后缀(两边规范化),加 `TestClassifyDriftIPMaskAlign` 回归测试
- 248(有 MARK 白名单实例)验证 external_tamper:多次迭代修复对齐问题--
  - ① 链跳转规则(`-j MYFW-*`)被算 extra:parseActualRuleKey 跳过跳转规则
  - ② actual 含 expected 链外的基础设施规则(conntrack 等):classifyDrift 只对比 expected 涉及链(`expChains` 过滤)
  - ③ `CompiledRule.Chain` 不带 MYFW- 前缀(`MARKMANGLE`),actual 链名带前缀(`MYFW-MARKMANGLE`):parseActualRuleKey 去 `MYFW-` 前缀
  - ④ 打标规则用 `--set-xmark 0xf/0xffffffff` 非 `--set-mark`:支持 `--set-xmark` + `/` 掩码处理,十六进制转十进制
  - 精确复现测试(`TestClassifyDriftReal248Debug`):expected 3 条 key 与 actual 4 条 key 完全对齐,`extra=1 missing=0 external_tamper` ✅
  - 线上分类结论 external_tamper 正确;数字偶有偏差(extra=2 vs 1)是异步拉取时序/规则残留导致 actual 含额外规则,非逻辑 bug(启发式局限,设计已声明)
- 自愈链路验证:248/249 加陌生规则后,OnSync 触发重新下发,规则被自动清除 ✅
