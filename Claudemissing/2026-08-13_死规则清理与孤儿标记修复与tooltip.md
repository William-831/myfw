# 死规则清理 + 249 无法移除修复 + 全量悬停说明

> 2026-08-13。用户指令:删除平台死规则;发现 249 存在无法移除的规则;要求功能按钮/标签加悬停介绍。
> 状态:✅ 已完成(TDD 红→绿 + 部署验证)。

## 背景与根因

1. **死规则**：判定= enabled + 有命中统计 + packets=0 + 创建超阈值。用户决策:阈值 7 天 → **3 天**。
2. **249 实例 3「允许ssh」无法移除**：
   - 根因:实例 `pending_delete=true + pending_delete_task_id=t_6a81d658`,但该任务 2026-08-07 已 `rolled_back`(manual rollback by admin)。回滚发生在**旧版本代码**(无 restorePendingDelete),实例标记残留 → 前端"移除"按钮 `:disabled="inst.pending_delete"` 永久禁用,用户无法再移除。
   - 这是孤儿标记:关联任务已终态(非 confirm_wait)但实例标记未清。
3. **tooltip 缺失**：状态标签与操作按钮无悬停说明,死规则含义不可见。

## 方案与实现

### 一、孤儿 pending_delete 标记清理(代码根治 + 线上修复)

`coordinator.go` 新增 `cleanOrphanPendingDelete(ctx)`,在 `Start()` 中 `recoverOnStart` 后调用。逻辑:
- 查 `pending_delete=true AND pending_delete_task_id != ''` 的实例,逐个查关联任务:
  - 任务 `confirm_wait` → 保护期内,不动
  - 任务 `confirmed` → 用户已确认移除但 DB 未清(理论罕见) → `purgePendingDelete` 补删
  - 任务 `rolled_back` → 移除被回滚,节点规则已恢复 → `restorePendingDelete` 恢复(启用+已下发+清标记)
  - 任务不存在/其他终态(failed 等) → 保守仅清标记,保持 enabled 现值,可重新操作

TDD:新增 `TestCleanOrphanPendingDelete`(4 场景:rolled_back 恢复/confirmed 补删/任务缺失清标记/confirm_wait 不动),红→绿。

**线上效果**:249 实例 3 启动即恢复(`enabled=true, pending_delete=false`),"移除"按钮恢复可用。

### 二、死规则阈值 7→3 天

`iptables_routes.go` `deadRuleThresholdDays 7 → 3`。测试补边界用例 `boundary-rule`(创建 4 天,3 天阈值下应 dead=true,旧 7 天逻辑 false),红→绿。

### 三、全量悬停说明(前端 NodePolicies.vue)

所有操作按钮 + 状态标签包 `el-tooltip`:
- **顶部操作**:新建策略 / 从模板实例化 / 下发节点(全量对齐) / 同步全部漂移 / 仅看死规则
- **状态标签**:模板 / ⚠模板已更新(已有) / 待确认移除 / ⚠链不可用 / 未下发 / 已下发 / 待移除 / **死规则(「创建3天没命中(启用+已采集+packets=0),建议移除」)** / 启用·禁用
- **实例 foot**:命中(pkts/bytes) / 启用开关 / 预演 / 编辑参数 / 同步模板 / 移除
