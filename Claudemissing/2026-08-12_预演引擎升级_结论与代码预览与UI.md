# 流量预演引擎升级:自然语言结论 + 代码预览 + UI 精致化

> 2026-08-12。用户反馈:预演效果很好,提三点改进--UI 更高级、后端返回自然语言结论、加代码预览对着看模拟过程。
> 状态:✅ 已完成(TDD 红→绿 + 全量 go test/vet + vite build 通过)。

## 现状

- 后端 `internal/controller/simulator/engine.go`:`Evaluate(flow,rules,chains,sets) *Result`,返回 `Verdict/Steps/Note`。`Step{chain,rule_id,action,mark,matched,note}`,无命令文本。`Note` 仅 PASS 时有内容。
- 路由 `simulate_routes.go`:`POST /api/v1/simulate` 返回 `{verdict,steps,note}`。
- 前端 `web/src/views/NodePolicies.vue` 预演抽屉:顶部五元组表单 + 左 9 栏"预期目标" + 右 15 栏水平通道流程图(入口→规则节点→终点,光点动画)。水平通道规则多时挤压(min-width 84px),无代码展示,无结论文案。

## 改进设计

### 改进 1:后端自然语言结论(Conclusion)

`Result` 增加字段 `Conclusion string`。`Evaluate` 末尾调用纯函数 `buildConclusion(flow, res)` 拼接,依据:
- 入参五元组(源/目的/协议/端口/方向)
- 最终 verdict
- 命中的终止规则(链名/规则 id/动作/MARK 值)

结论示例:
- **ACCEPT**:`源 10.0.0.5 的 TCP 流量(目的 192.168.1.10:443,方向 FORWARD)在 MYFW-MARKACL-FWD 链命中规则 r-xxx,动作 ACCEPT,流量将被放行。`
- **DROP**:`源 10.0.0.5 的 TCP 流量(目的 :443)在 MYFW-MARKACL-FWD 链命中规则 r-xxx,动作 DROP,流量将被拦截。`
- **MARK→ACCEPT**(打标后白名单放行):`源 10.0.0.5 的 TCP 流量先在 MYFW-MARKMANGLE 链被打标 0x10(规则 r-m1),随后在 MYFW-MARKACL-IN 链命中 match_mark 规则 r-a1 放行(ACCEPT)。`
- **PASS**:`源 10.0.0.5 的 TCP 流量(目的 :443)未命中任何终止规则,遍历结束(PASS),交由系统链默认策略处理(通常放行)。无状态仿真未建模 conntrack 放行。`

字段为空/IP 为空时降级为"任意源/任意目的"。

### 改进 2:代码预览(Step.Command)

`Step` 增加字段 `Command string`,存放该规则编译后的 iptables 命令文本。新增纯函数 `formatCommand(rule *myfwv1.CompiledRule) string`,字段对齐 `CompiledRule`(Source/Destination/SourceGroup/DestinationGroup/Protocol/PortRange/Action/Mark/MatchMark/Chain)。

命令格式(对齐真实 driver `iptables.go compileRule`):
```
iptables -A MYFW-MARKACL-FWD -s 10.0.0.0/24 -p tcp --dport 443 -m mark --mark 0x10 -j ACCEPT
iptables -t mangle -A MYFW-MARKMANGLE -s 10.0.0.0/24 -p tcp --dport 443 -j MARK --set-mark 0x10
```

- 地址组用 `-m set --match-set MYFW-<group> src/dst`(对齐 driver)
- MARK 动作 `-j MARK --set-mark 0x10`;match_mark 条件 `-m mark --mark 0x10`
- DNAT/SNAT 也输出命令文本(标注"仿真不支持,仅展示")
- mangle 链规则带 `-t mangle`

在 `evalChainRules` 构造 step 时填充 `Command = formatCommand(r)`。

### 改进 3:UI 精致化

抽屉布局重构(保持 `size="68%"`):

```
┌─ 表单栏(五元组 + 预演按钮) ─────────────────────────────┐
├─ verdict 横幅(大徽章+图标+结论文案,全宽) ────────────────┤
├──────────────┬─────────────────────────────────────────┤
│ 左 8 栏       │ 右 16 栏:垂直步骤流                      │
│ 预期目标      │  ┌ 入口(INPUT/FORWARD/OUTPUT)           │
│ (实例信息+    │  │  chain: MYFW-MARKMANGLE               │
│  预期文案)    │  │  ▸ MARK  r-m1  [打标 0x10]            │
│              │  │  iptables -t mangle -A ... MARK ...    │
│              │  ├  chain: MYFW-MARKACL-FWD               │
│              │  │  ▸ ACCEPT r-a1 [命中] ← 终止           │
│              │  │  iptables -A ... -j ACCEPT             │
│              │  └ 终点: ACCEPT                           │
└──────────────┴─────────────────────────────────────────┘
```

要点:
1. **verdict 横幅**:全宽卡片,左侧大图标(✓放行/✕拦截/→放行),右侧 verdict 文字 + `Conclusion` 结论文案。配色 ACCEPT 绿/DROP 红/REJECT 橙/PASS 灰。
2. **垂直步骤流**替代水平通道:每步一张卡片,左侧时间轴竖线连接。命中卡片高亮(边框+底色+放大),未命中半透明(opacity .55)。终止步加"终止"角标。规则多时纵向滚动,不再挤压。
3. **代码块**:每张步骤卡片底部内嵌 iptables 命令(等宽字体,深色代码主题 `#1e1e2e` 底 + 浅色字,命中行高亮左边框)。默认展开命中步、折叠未命中步(或全部展开,按步骤数自适应:≤6 全展开,>6 仅命中展开)。
4. **光点动画**:时间轴竖线上光点自上而下流动,DROP/REJECT 停在命中步,ACCEPT/PASS 走到底。
5. 左栏"预期目标"精简:关键字段(协议/端口/源/目的/动作)+ 预期文案,与右侧实际结果形成对照。
