# 保护期动作合并接管方案

> 2026-08-12。目标:策略实例处于保护期(confirm_wait)时,用户发起新动作(启用↔禁用/移除/下发),系统作废旧任务、生成新快照、重置保护期、审计串联;UI 明确提示"动作已合并接管",未确认前状态显示保护期内,正确下发后才显示已下发/已应用。

## 一、现状与问题

### 现状链路
| 入口 | 行为 | 保护期检查 |
|------|------|-----------|
| `PUT /instances/:id`(开关/参数编辑) | 直接 `db.Save`,**不触发下发** | 无 |
| `DELETE /instances/:id`(移除) | applied=false 直接删;applied=true 走 `SubmitRemoval`(建 task+标记 pending_delete+AutoApprove dispatch) | 无 |
| `POST /nodes/:id/dispatch`(节点级下发) | 走 `Submit`(AutoApprove dispatch) | 无 |
| `HasInFlight(nodeID)` | 查 pending_approval/dispatching/applying/confirm_wait | **仅 OnSync 自愈去重用,不阻止人工操作** |

### Agent 快照语义(关键)
`internal/agent/handler/handler.go:61` `last map[string]string` **按 TaskId 保留**每次 Apply 前快照,Confirm 释放、Rollback 恢复。

### 三大问题映射用户痛点
1. **"系统没反应"**:开关切换走 PUT 只改 DB,节点不动;用户以为生效,实际未下发。
2. **"系统在乱跑"**:旧 task t_A 在 confirm_wait,Agent 持 `last["t_A"]`;新 task t_B 又 Apply,Agent 新增 `last["t_B"]`(前置态=t_A 已下发态)。t_A 超时回滚用 `last["t_A"]` 恢复 → **把 t_B 的变更也冲掉**。
3. **状态错乱**:PUT 直接改 enabled,前端直接显示"已禁用",但节点规则还在(旧 task 未回滚);违反"未确认前状态应在保护期内"。

## 二、设计目标

新动作到达时,若目标节点有 confirm_wait 任务:
1. **作废旧任务**:cancel 回滚定时器,置 `superseded` 终态,通知 Agent 释放旧快照(复用 Confirm 语义)。
2. **生成新快照**:新 task 基于最新 DB 状态编译,Agent 重新 Snapshot(前置态=旧 task 已下发态)。
3. **重置保护期**:新 task 起全新 confirm_deadline。
4. **审计串联**:旧 task `task.superseded`(detail.superseded_by=新 task),新 task `task.submit`(detail.superseded=[旧 task 列表])。
5. **UI 接管提示**:开关/移除/下发均 loading+明确文案;状态标签"保护期接管中";旧 banner 自动消失。

## 三、后端改造

### 3.1 新增任务终态 `TaskSuperseded`
`internal/model/task.go`:
```go
TaskSuperseded TaskStatus = "superseded" // 被新动作接管,不再回滚
```
`HasInFlight` 不含 superseded(终态)。

### 3.2 新增 `Coordinator.SupersedeInFlight`
`internal/controller/task/coordinator.go`:
```go
// SupersedeInFlight 作废目标节点所有在途任务,为新动作让路。
// - confirm_wait:置 superseded + cancelTimer + sendConfirmToAgent(释放 Agent 旧快照) +
//   restorePendingDelete(旧移除 task 作废则实例恢复,供新动作重新决定)
// - pending_approval:置 superseded(未下发,无 Agent 快照)
// - dispatching/applying:返回 error,调用方应拒绝新动作(执行中不可接管)
// 返回被作废的 task 列表,供审计串联。
func (co *Coordinator) SupersedeInFlight(ctx context.Context, nodeID, newTaskID, reviewer, reason string) ([]*model.Task, error)
```
事务内批量改状态;事务外 cancelTimer + sendConfirmToAgent + restorePendingDelete + 审计。

### 3.3 三个写入口接入"接管"
统一前置:`co.preDispatch(ctx, nodeID, reviewer, scene)` → 内部调 `SupersedeInFlight`。

| 入口 | 改造 |
|------|------|
| `Submit`(节点级下发) | dispatch 前调 SupersedeInFlight;dispatching/applying 在途则返回 409"节点有任务执行中,请稍候" |
| `SubmitRemoval`(移除) | 同上;且若旧 task 正是移除同一实例,Supersede 已 restorePendingDelete 恢复实例,新移除重新走标记+dispatch |
| `PUT /instances/:id` **仅 enabled 字段变更时** | 触发 dispatch(开关即动作):先 Save DB,再 Submit(AutoApprove);离线则回退纯 DB+applied=false 待下发 |

**开关自动下发的边界**:
- 节点在线 → Save + Submit(AutoApprove) + 轮询 → confirm_wait 提示接管。
- 节点离线 → 仅 Save + applied=false,提示"节点离线,已记录,上线后请下发"。
- 纯参数编辑(enabled 未变) → 保持现状(纯 Save + applied=false),不触发接管。

### 3.4 dispatching/applying 在途的拒绝
新动作到达时若节点有 dispatching/applying 任务(执行中,Agent 正在 Apply),**不接管,直接拒绝**(409),前端禁用按钮并提示"节点有任务执行中,请稍候"。接管仅针对 confirm_wait/pending_approval(可安全作废)。

## 四、前端改造(web/src/views/NodePolicies.vue)

### 4.1 开关切换重构
```
handleToggle(inst):
  旧: PUT 改 enabled
  新: PUT 改 enabled -> 若节点在线: dispatch(AutoApprove) -> 轮询 task
       -> confirm_wait: ElMessage.success("动作已接管保护期,新状态生效中,待确认")
       -> failed: ElMessage.error("下发失败,已回滚")
       -> 离线: ElMessage.warning("节点离线,已记录变更,上线后请下发")
```
开关按钮 loading 态,防止重复点击。

### 4.2 状态标签新增"保护期接管中"
节点有 confirm_wait 任务时,该节点所有受影响实例角标显示"⏳ 保护期接管中"(el-tag type=warning effect=dark),tooltip:"新动作已下发,旧任务已作废,保护期已重置,待确认"。
- 覆盖现有"待移除/未下发"标签的歧义:接管期间不显示"已禁用",而显示"保护期接管中"。

### 4.3 顶部 banner 接管提示
旧 banner("该节点有保护期待确认任务")在新动作接管后,改为:"✅ 旧任务 t_xxx 已被新动作 t_yyy 接管,保护期已重置,请确认新状态"。guardTask 指向新 task。

### 4.4 按钮禁用规则
- 节点有 dispatching/applying 任务 → 全部操作按钮禁用 + tooltip"任务执行中"。
- 节点有 confirm_wait 任务 → 操作按钮**不禁用**(允许接管),tooltip"将作废当前保护期任务并重置保护期"。

## 五、审计串联

| 对象 | action | scene | result | detail |
|------|--------|-------|--------|--------|
| 旧 task | `task.superseded` | normal | pending | `{superseded_by: t_yyy, reason}` |
| 新 task | `task.submit` | normal | pending | `{superseded: [t_xxx,...], reason:"保护期动作合并接管"}` |

审计日志按 task_id 串联,可追溯"t_A → 被 t_B 接管 → t_B 确认/回滚"完整链。

## 七、边界与风险

| 场景 | 处理 |
|------|------|
| 旧 task 旧移除被接管,新动作是"启用" | Supersede restorePendingDelete 恢复实例,新动作 dispatch 下发该实例规则 |
| 旧 task 旧移除被接管,新动作是"移除同实例" | restorePendingDelete 恢复后,SubmitRemoval 重新标记 pending_delete + 新 task |
| Agent 离线时新动作 | dispatch 失败,task failed;前端回退提示;旧 task 已 superseded(用户主动作废) |
| 多实例节点,一个 confirm_wait | SupersedeInFlight 按节点级作废(节点单任务队列模型,符合现有 HasInFlight 语义) |
| 旧 task AutoConfirm 自愈任务 | 自愈不进 confirm_wait(apply 成功即 confirmed),无 superseded 场景 |

## 十、实现记录(2026-08-13 完成,部署验证通过)

### 实现要点(与方案的差异)

1. **接管挂载点修正**:SupersedeInFlight 挂在 `approveAndDispatch` 编译成功后、Send 前,而非 Submit/SubmitRemoval 各自调用——所有 dispatch 路径(Submit 节点级/SubmitRemoval/SubmitRuleSet/人工 Approve)统一获得接管能力,编译失败不动旧任务。
2. **前端 toggleEnabled 保持两步式**(PUT 改 DB + dispatchNode),后端 PUT 不触发 dispatch(避免双重下发)。"开关即动作"由前端两步 + 后端接管共同实现。
3. **sentinel 错误**:新增 `task.ErrNodeBusy`,SupersedeInFlight 遇 dispatching/applying 任务返回它,server 层 `errors.Is` 映射 409("节点有任务执行中,请稍候再试")——dispatch 与 DELETE 移除两个入口。

### 改动文件

- `internal/model/task.go`:TaskSuperseded 终态
- `internal/controller/task/coordinator.go`:SupersedeInFlight + ErrNodeBusy + approveAndDispatch 接入
- `internal/controller/task/coordinator_test.go`:6 个新测试(confirm_wait 接管/移除恢复实例/pending_approval/dispatching 拒绝/无在途 noop/approveDispatch 集成)
- `internal/controller/server/template_routes.go`:dispatch + DELETE 移除 409 映射
- `internal/controller/server/template_supersede_test.go`:2 个新测试(节点 busy 409 / dispatch 接管 confirm_wait)
- `web/src/views/NodePolicies.vue`:inflightTasks/nodeInGuard/nodeBusy 计算 + refreshInflight(轮询 confirm_wait/dispatching/applying/superseded)+ 接管文案 + 状态标签"⏳ 保护期接管中" + banner 接管提示 + nodeBusy 按钮禁用
